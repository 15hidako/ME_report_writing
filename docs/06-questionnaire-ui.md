追加58語の決定は[採用決定](research/men-esthe-2026-10-23/planning/adoption58-decision.json)、今回の確認結果は[58語追加の検証記録](research/men-esthe-2026-10-23/planning/adoption58-validation.json)で管理する。以下の配置数、表、スクリーンショット、テスト件数は先行29語の組み込み時点の記録であり、87語の検証結果とは分けて読む。

先行29語を通常の質問票へ組み込んだ際は、既存のA〜F、6軸の星評価、自由メモ、段階別チップを使い、必要な欄だけで候補を開く構成とした。実装、レビュー、検証、文書更新は利用者の指定によりGPT内で完結した。[確認用プロトタイプ](prototypes/questionnaire-enrichment.html)も本体と同じフォームと候補操作を使い、架空の入力だけを保存せずに扱う。追加58語もGPT内で扱う。

## 追加58語の操作

追加58語も既存の折りたたみを使う。Bの評価メモに加え、Dの段階メモと残念ポイントには、手入力を残したまま表現を追記する。段階の観察は従来どおり、選んだ段階のチェックとして保存する。新しい保存フィールドは設けない。

追記の重複判定には、従来の「／」「/」「。」「；」「;」と改行に加え、読点「、」とカンマ「,」も区切りとして使う。部分一致する否定文と候補語は、同じ独立した表現とは扱わない。星や他の段階の選択は変えない。

`price_clarity_05` は「追加内容と料金の説明があった」と表示し、説明された実際の段階を本人が選ぶ。前回計画にあった「施術前」という限定で段階を決めつけない。表示箇所や件数、今回の動作確認は[58語追加の検証記録](research/men-esthe-2026-10-23/planning/adoption58-validation.json)を参照する。

## 先行29語の配置と操作

背景の濃い紫、ピンクの選択状態、金色の見出しと星、既存の日本語フォントを維持する。フォームの最大幅720px、余白14px、セクションの角丸14pxも引き継ぐ。A〜Fの順序と開閉、6軸の星とメモ、Cの属性チップ、Eのセリフと再訪意向は従来の操作を踏襲する。

追加するのは、Bの評価メモ下部とDの各段階にある折りたたみのみである。配置箇所はBが4か所、Dが5か所で、初期状態は閉じた状態とする。Dに保存済みの追加候補がある場合は、該当する折りたたみを開いて選択状態を表示する。

先行候補は29語だが、表示場所を分けるため、ボタンの配置数はBが27個、Dが9個の計36個となる。すべてを同時に表示する構成ではない。候補ID、表示語、出典ID、配置の対応は[配置データ](research/men-esthe-2026-10-23/planning/ui-first-batch.json)に記録した。

## 先行29語のBの評価メモ

| 評価欄 | 候補数 | 折りたたみ内の内容 |
|---|---:|---|
| 顔 | 4 | 写真との印象。体型だけの候補は含めない |
| スタイル | 4 | 写真との印象と体型の違い |
| 接客 | 9 | 話し方と働きかけ、自分との相性、接客の受け止め方 |
| マッサージ技術 | 10 | 希望と強さ、手技の受け止め方 |

折りたたみの見出しは「メモへ追加する表現（件数）」とする。ボタンは既存チップと同じ形とし、押すと該当評価欄のメモ末尾へ表現を追記する。顔で押した内容をスタイルへ複製することはない。

追記操作であるため、選択中の色や押下状態は付けない。既存のメモを残したまま、区切りとして「 ／ 」を挟んで追記する。すでに独立した表現として同じ語が含まれている場合は重複して追加しない。たとえば「話しやすかったとは言えない」は「話しやすかった」と一致扱いにしない。区切りとして扱うのは「／」「/」「。」「；」「;」と改行であり、比較時のみ区切り前後の空白を除外する。

削除や書き換えは通常の入力欄で行う。候補を再度押して文章を削除する操作は設けない。手入力後に候補の選択状態を推測したり、候補から星を変更したりもしない。追記時には通常の入力変更と同じ通知を出し、既存の未保存判定へつなぐ。

相反する感想を入力しても自動で削除しない。部位、話題、時間帯などの違いは、本人がメモへ書き足せる。実際のセリフを生成する候補には使用しない。

`assessment_06` は「重点的にケアする部位の確認はなかった」として表示する。元の「特に確認はなかった」から意味を広げず、根拠を確認した範囲に限定する。

## 先行29語のDの段階別チップ

| 配置する段階 | 追加候補 |
|---|---|
| 対面〜シャワー | 笑顔で迎えられた、緊張がほぐれた |
| うつ伏せ前半 | 手のひらまでケア、ストレッチあり |
| オイル〜SP展開 | 手のひらまでケア、ストレッチあり |
| 仰向け | 手のひらまでケア、ストレッチあり |
| その後 | 見送りがあった |

従来のチップの後に「観察候補を開く（件数）」を配置する。ここでは従来どおり、押すと選択、再度押すと解除される。選択中の色や押下状態も既存の表示を踏襲する。

手のひらのケアとストレッチは複数の段階に配置するが、選択は押した段階のみに保存する。段階を推測して移動させたり、他の段階へ一括で反映したりはしない。出来事が起きた別の段階が分かる場合は、その段階の自由メモに残す。段階が不明な出来事の共通欄は新設しないため、無理に段階を選ばない。対面後に緊張がほぐれた場合も、対面で起きた出来事としては選択しない。

「会話が弾んだ」「パウダー」「その後の会話」には既存の選択肢を使用し、同義の候補は追加しない。

## 保存済みの表現

先行29語の組み込み前には、保存済みの段階別チェックが選択肢定義にないと、編集と再保存で失われる問題があった。当時の実装で、元の段階の選択済みチップとして復元するように修正した。

保存された文字列のうち現在の候補にないものは、元の段階に「保存済みの観察」として表示する。初期状態では選択済みとし、本人が押して解除するまで残す。新しいラベルへの自動変換は行わない。チェックは観察を選んだ集合として扱い、同じ段階の完全一致する文字列は一つにまとめる。保存時の配列順序は画面の並びにそろえる。重複件数や元の配列順序の完全一致は保証しない。

追加候補と保存済みの表現は、既存の段階別チップと同じ収集範囲に配置する。再表示後も文字列と段階を保持し、その段階の出来事として記事素材へ出力する。再訪を新規入力する場合には、前回の評価理由や観察を自動選択しない。

候補語を追記する時点では本人の入力文字列を維持する。保存時には現行の収集処理がメモ前後の空白を除去するため、保存前後の文字列が常に完全一致するとは扱わない。

## 小さい画面とキーボード

追加ボタンは高さ44px以上とし、長い候補は欄内で折り返して横スクロールを発生させない。幅380px以下では評価名と星を縦に並べ、星が画面からはみ出さないようにする。色、書体、星の形状は変更しない。

開閉には標準の `details` と `summary` を使い、Tab、Enter、Spaceで操作できるようにする。追加ボタンには、どの評価メモへ追記するかを読み上げる名前を付ける。選択チップには押下状態を付け、追記ボタンには付けない。フォーカスは既存のピンク色で表示し、追記後も操作したボタンに残す。重複により追加しなかった場合も、状態メッセージで通知する。

## 組み込みの確認項目

| 対象 | 合格条件 |
|---|---|
| 手入力 | 追記しても元の文が残る。繰り返し押しても同じ独立語が重複しない。本人の書き換えを消さない |
| 評価 | 候補の追記と星が独立し、相反する記録も勝手に削除しない |
| 段階 | 同じ表現を別の段階で選んでも独立し、一つの段階だけ解除できる |
| 旧値 | 未知の文字列も、編集、再保存、書出し、読込、記事素材への出力で保持する |
| 再訪 | 前回の主観や出来事を新しい訪問へ持ち込まない |
| 画面と操作 | 狭い画面で候補が切れず、キーボードでも開閉と追記、選択と解除ができる |

入力時間と記事の具体性は、実際の訪問メモで別途評価する。5分以内という現行の目標を、画面検証だけで達成したとは扱わない。来店理由や総評理由などの新項目は全件却下され、[拡充案](05-questionnaire-enrichment.md)には検討履歴として残す。
