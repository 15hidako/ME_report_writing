# 質問票の候補表示と操作

検討日：2026年10月23日

既存のA〜F、6軸の星評価、自由メモ、段階別チップを使い、先行候補29語を追加する案をまとめた。候補は必要な欄で開く。質問項目を増やす前に、書き残したい評価理由や場面を思い出せるようにする。

今回のUI検討は、利用者の指定によりGPTモデルで進めた。[確認用プロトタイプ](prototypes/questionnaire-enrichment.html)は既存のフォーム生成、チップ操作、記事素材への出力を再利用している。架空の入力だけをページ内で扱い、保存処理は持たない。実際の質問票への組み込みは未実施である。

## 既存画面の踏襲

背景の濃い紫、ピンクの選択状態、金色の見出しと星、既存の日本語フォントを保つ。フォームの最大幅720px、余白14px、セクションの角丸14pxも引き継ぐ。A〜Fの順序と開閉、6軸の星とメモ、Cの属性チップ、Eのセリフと再訪意向は従来の操作を使う。

追加するのは、Bの評価メモの下とDの各段階にある折りたたみだけ。Bは4か所、Dは5か所で、最初は閉じる。Dに保存済みの追加候補がある場合は、該当する折りたたみを開いて選択を見せる。

先行候補は29語だが、表示場所を分けるため、ボタンの配置数はBが27個、Dが9個の計36個となる。すべてを同時に表示する構成ではない。候補ID、表示語、出典ID、配置の対応は[配置データ](research/men-esthe-2026-10-23/planning/ui-first-batch.json)に残した。

## Bの評価メモ

| 評価欄 | 候補数 | 折りたたみ内の内容 |
|---|---:|---|
| 顔 | 4 | 写真との印象。体型だけの候補は含めない |
| スタイル | 4 | 写真との印象と体型の違い |
| 接客 | 9 | 話し方と働きかけ、自分との相性、接客の受け止め方 |
| マッサージ技術 | 10 | 希望と強さ、手技の受け止め方 |

折りたたみの見出しは「メモへ追加する表現（件数）」とする。ボタンは既存チップと同じ形を使い、押すとその評価欄のメモ末尾へ表現を追記する。顔で押した内容をスタイルへ複製することはない。

これは追記操作なので、選択中の色や押下状態を付けない。既存メモを残し、区切りとして「 ／ 」を挟んで追記する。すでに独立した表現として同じ語が入っている場合は重複追加しない。たとえば「話しやすかったとは言えない」は「話しやすかった」と一致扱いにしない。区切りとして扱うのは「／」「/」「。」「；」「;」と改行で、比較時だけ区切り前後の空白を除く。

削除や書き換えは通常の入力欄で行う。候補をもう一度押して文章を消す操作は設けない。手入力後に候補の選択状態を推測したり、候補から星を変えたりもしない。追記時には通常の入力変更と同じ通知を出し、実装時には既存の未保存判定へつなぐ。

相反する感想を入れても自動で消さない。部位、話題、時間帯などの違いは、本人がメモへ書き足せる。実際のセリフを作る候補には使わない。

`assessment_06` は「重点的にケアする部位の確認はなかった」として表示する。元の「特に確認はなかった」から意味を広げず、根拠を確認した範囲に限定する。

## Dの段階別チップ

| 配置する段階 | 追加候補 |
|---|---|
| 対面〜シャワー | 笑顔で迎えられた、緊張がほぐれた |
| うつ伏せ前半 | 手のひらまでケア、ストレッチあり |
| オイル〜SP展開 | 手のひらまでケア、ストレッチあり |
| 仰向け | 手のひらまでケア、ストレッチあり |
| その後 | 見送りがあった |

従来のチップの後に「観察候補を開く（件数）」を置く。ここでは従来どおり、押すと選択、もう一度押すと解除する。選択中の色と押下状態も既存の表示を使う。

手のひらのケアとストレッチは複数の段階に置くが、選択は押した段階だけに保存する。段階を推測して移したり、他の段階へ一括で反映したりしない。段階が分からない場合や表示場所に合わない場合は、分かる範囲を自由メモに残す。対面後に緊張がほぐれた場合も、対面で起きたこととして選ばない。

「会話が弾んだ」「パウダー」「その後の会話」には既存の選択肢を使う。同義の候補を追加しない。

## 保存済みの表現

現在のフォームには、保存済みの段階別チェックが選択肢定義にないと、編集と再保存で失われる問題がある。組み込み時にはこれを先に解消する。

保存された文字列のうち現在の候補にないものは、元の段階に「保存済みの観察」として表示する。最初は選択済みとし、本人が押して解除するまで残す。新しいラベルへの自動変換は行わない。同じ段階の同一文字列は一つのチップとして扱う。

追加候補と保存済みの表現は、既存の段階別チップと同じ収集範囲に置く。再表示後も文字列と段階を保持し、その段階の出来事として記事素材へ出力する。再訪を新規入力する場合には、前回の評価理由や観察を自動で選択しない。

候補語を追記する時点では本人の入力文字列を維持する。保存時には現行の収集処理がメモの先頭と末尾の空白を除くため、保存前後の文字列が常に完全一致するとは扱わない。

## 小さい画面とキーボード

追加ボタンは高さ44px以上とし、長い候補は欄内で折り返す。横スクロールは増やさない。幅380px以下では評価名と星を縦に並べ、星が画面からはみ出さないようにする。色、書体、星の形は変えない。

開閉には標準の `details` と `summary` を使い、Tab、Enter、Spaceで操作できるようにする。追加ボタンには、どの評価メモへ追記するかを読み上げる名前を付ける。選択チップには押下状態を付け、追記ボタンには付けない。フォーカスは既存のピンク色で表示し、追記後は操作したボタンに残す。重複追加をしなかった場合も、状態メッセージで伝える。

## 確認用プロトタイプ

リポジトリで `npm run dev -- --host 127.0.0.1 --port 5187 --strictPort` を起動し、`http://127.0.0.1:5187/docs/prototypes/questionnaire-enrichment.html` を開く。HTML単体を直接開く使い方には対応しない。

「記事素材を確認」で既存の出力処理を通した素材を表示し、「入力を再表示」で編集後の復元を試せる。どちらもページ内の処理であり、訪問履歴には保存しない。ページを再読み込みすると架空の初期入力に戻る。

## 組み込み時の確認

| 対象 | 合格条件 |
|---|---|
| 手入力 | 追記しても元の文が残る。繰り返し押しても同じ独立語が重複しない。本人の書き換えを消さない |
| 評価 | 候補の追記と星が独立し、相反する記録も勝手に削除しない |
| 段階 | 同じ表現を別の段階で選んでも独立し、一つの段階だけ解除できる |
| 旧値 | 未知の文字列も、編集、再保存、書出し、読込、記事素材への出力で保持する |
| 再訪 | 前回の主観や出来事を新しい訪問へ持ち込まない |
| 画面と操作 | 狭い画面で候補が切れず、キーボードでも開閉と追記、選択と解除ができる |

入力時間と記事の具体性は、実際の訪問メモで別途評価する。5分以内という現行の目標を、今回の画面検証だけで達成したとは扱わない。来店理由や総評理由などの新項目は、[拡充案](05-questionnaire-enrichment.md)に記した次段階の検討として残す。
