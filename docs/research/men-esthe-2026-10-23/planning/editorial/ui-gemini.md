# 質問票の候補表示と操作

検討日：2026年10月23日

既存のA〜F、6軸の星評価、自由メモ、段階別チップを活用し、先行候補29語を追加する案をまとめた。候補は必要な欄でのみ展開する。質問項目を増やす前に、書き残したい評価理由や場面を想起しやすくすることを目的としている。

今回のUI検討は、利用者の指定によりGPTモデルで進めた。[確認用プロトタイプ](prototypes/questionnaire-enrichment.html)は既存のフォーム生成、チップ操作、記事素材への出力を再利用している。架空の入力のみをページ内で扱い、保存処理は持たない。実際の質問票への組み込みは未実施である。

## 既存画面の踏襲

背景の濃い紫、ピンクの選択状態、金色の見出しと星、既存の日本語フォントを維持する。フォームの最大幅720px、余白14px、セクションの角丸14pxも引き継ぐ。A〜Fの順序と開閉、6軸の星とメモ、Cの属性チップ、Eのセリフと再訪意向は従来の操作を踏襲する。

追加するのは、Bの評価メモ下部とDの各段階にある折りたたみのみである。配置箇所はBが4か所、Dが5か所で、初期状態は閉じた状態とする。Dに保存済みの追加候補がある場合は、該当する折りたたみを開いて選択状態を表示する。

先行候補は29語だが、表示場所を分けるため、ボタンの配置数はBが27個、Dが9個の計36個となる。すべてを同時に表示する構成ではない。候補ID、表示語、出典ID、配置の対応は[配置データ](research/men-esthe-2026-10-23/planning/ui-first-batch.json)に記録した。

## Bの評価メモ

| 評価欄 | 候補数 | 折りたたみ内の内容 |
|---|---:|---|
| 顔 | 4 | 写真との印象。体型だけの候補は含めない |
| スタイル | 4 | 写真との印象と体型の違い |
| 接客 | 9 | 話し方と働きかけ、自分との相性、接客の受け止め方 |
| マッサージ技術 | 10 | 希望と強さ、手技の受け止め方 |

折りたたみの見出しは「メモへ追加する表現（件数）」とする。ボタンは既存チップと同じ形状とし、押下すると該当評価欄のメモ末尾へ表現を追記する。顔で押した内容をスタイルへ複製することはない。

追記操作であるため、選択中の色や押下状態は付与しない。既存のメモを残したまま、区切りとして「 ／ 」を挟んで追記する。すでに独立した表現として同じ語が含まれている場合は重複して追加しない。たとえば「話しやすかったとは言えない」は「話しやすかった」と一致扱いにしない。区切りとして扱うのは「／」「/」「。」「；」「;」と改行であり、比較時のみ区切り前後の空白を除外する。

削除や書き換えは通常の入力欄で行う。候補を再度押して文章を削除する操作は設けない。手入力後に候補の選択状態を推測したり、候補から星を変更したりもしない。追記時には通常の入力変更と同じ通知を発行し、実装時には既存の未保存判定へ連動させる。

相反する感想を入力しても自動で削除しない。部位、話題、時間帯などの違いは、本人がメモへ書き足せる。実際のセリフを生成する候補には使用しない。

`assessment_06` は「重点的にケアする部位の確認はなかった」として表示する。元の「特に確認はなかった」から意味を広げず、根拠を確認した範囲に限定する。

## Dの段階別チップ

| 配置する段階 | 追加候補 |
|---|---|
| 対面〜シャワー | 笑顔で迎えられた、緊張がほぐれた |
| うつ伏せ前半 | 手のひらまでケア、ストレッチあり |
| オイル〜SP展開 | 手のひらまでケア、ストレッチあり |
| 仰向け | 手のひらまでケア、ストレッチあり |
| その後 | 見送りがあった |

従来のチップの後に「観察候補を開く（件数）」を配置する。ここでは従来どおり、押すと選択、再度押すと解除される。選択中の色や押下状態も既存の表示を踏襲する。

手のひらのケアとストレッチは複数の段階に配置するが、選択は押した段階のみに保存する。段階を推測して移動させたり、他の段階へ一括で反映したりはしない。段階が分からない場合や表示場所に合わない場合は、分かる範囲を自由メモに残す。対面後に緊張がほぐれた場合も、対面で起きた出来事としては選択しない。

「会話が弾んだ」「パウダー」「その後の会話」には既存の選択肢を使用し、同義の候補は追加しない。

## 保存済みの表現

現在のフォームには、保存済みの段階別チェックが選択肢定義にないと、編集と再保存で失われる問題がある。組み込み時にはこれを先行して解消する。

保存された文字列のうち現在の候補にないものは、元の段階に「保存済みの観察」として表示する。初期状態では選択済みとし、本人が押して解除するまで残す。新しいラベルへの自動変換は行わない。同じ段階の同一文字列は一つのチップとして扱う。

追加候補と保存済みの表現は、既存の段階別チップと同じ収集範囲に配置する。再表示後も文字列と段階を保持し、その段階の出来事として記事素材へ出力する。再訪を新規入力する場合には、前回の評価理由や観察を自動選択しない。

候補語を追記する時点では本人の入力文字列を維持する。保存時には現行の収集処理がメモ前後の空白を除去するため、保存前後の文字列が常に完全一致するとは扱わない。

## 小さい画面とキーボード

追加ボタンは高さ44px以上とし、長い候補は欄内で折り返して横スクロールを発生させない。幅380px以下では評価名と星を縦に並べ、星が画面からはみ出さないようにする。色、書体、星の形状は変更しない。

開閉には標準の `details` と `summary` を使い、Tab、Enter、Spaceで操作できるようにする。追加ボタンには、どの評価メモへ追記するかを読み上げる名前を付与する。選択チップには押下状態を付与し、追記ボタンには付与しない。フォーカスは既存のピンク色で表示し、追記後も操作したボタンに残す。重複により追加しなかった場合も、状態メッセージで通知する。

## 確認用プロトタイプ

リポジトリで `npm run dev -- --host 127.0.0.1 --port 5187 --strictPort` を起動し、`http://127.0.0.1:5187/docs/prototypes/questionnaire-enrichment.html` を開く。HTML単体を直接開く構成には対応しない。

「記事素材を確認」で既存の出力処理を通した素材を表示し、「入力を再表示」で編集後の復元を試せる。いずれもページ内のみの処理であり、訪問履歴には保存しない。ページを再読み込みすると架空の初期入力に戻る。

## 組み込み時の確認

| 対象 | 合格条件 |
|---|---|
| 手入力 | 追記しても元の文が残る。繰り返し押しても同じ独立語が重複しない。本人の書き換えを消さない |
| 評価 | 候補の追記と星が独立し、相反する記録も勝手に削除しない |
| 段階 | 同じ表現を別の段階で選んでも独立し、一つの段階だけ解除できる |
| 旧値 | 未知の文字列も、編集、再保存、書出し、読込、記事素材への出力で保持する |
| 再訪 | 前回の主観や出来事を新しい訪問へ持ち込まない |
| 画面と操作 | 狭い画面で候補が切れず、キーボードでも開閉と追記、選択と解除ができる |

入力時間と記事の具体性は、実際の訪問メモで別途評価する。5分以内という現行の目標を、今回の画面検証だけで達成したとは扱わない。来店理由や総評理由などの新項目は、[拡充案](05-questionnaire-enrichment.md)に記した次段階の検討として残す。
