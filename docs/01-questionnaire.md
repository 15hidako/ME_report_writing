# 質問票設計

更新日：2026年10月23日

実装基準：`e33c331`（`main`、[PR #2](https://github.com/15hidako/ME_report_writing/pull/2)マージ済み）

調査した候補語は、先行29語に追加承認された58語を合わせて87語を採用済み。Bの評価メモ、Dの段階別チェックとメモ、既存の残念ポイント欄を使い、候補追加に伴う保存形式の変更は行っていない。利用方針は[記事執筆用質問票の拡充案](05-questionnaire-enrichment.md)を参照。

既存画面を踏襲した候補の表示と操作、実装と検証の結果は[UI仕様と組み込み記録](06-questionnaire-ui.md)にまとめた。通常の入力画面で利用でき、保存しない確認用プロトタイプも同じ実装を使う。

追加58語は、前回計画の優先35語と場面限定23語を全件承認したもの。新しい質問群10群（33の任意小問）は全件却下済み。この58語の組み込みでは、既存の質問と保存項目を使った。[採用決定と候補の記録](07-questionnaire-next-options.md)に内訳と意味の条件を残し、58語追加時の確認結果は[58語追加の検証記録](research/men-esthe-2026-10-23/planning/adoption58-validation.json)で管理する。

Dの6段階では、定番チェックと追加候補を選んだ順に保存する機能も実装済み。操作と旧記録の扱いはセクションDに記載する。実装前の[引継ぎ資料](archive/08-questionnaire-selection-order-handoff.md)は退役済みの検討記録として保管する。

設計原則: **訪問直後に片手・5分以内**で完了できること。
自由記述は最小限(合計5欄程度)、それ以外はタップ選択。
保存ボタンでlocalStorageへ記録し、後から追記・編集できる。入力途中の内容と選択順は、ページを開いている間のタブ切替で保持する。保存前のページ再読み込みや、ページを閉じた後の復元には対応していない。

セクションA(基本情報)は予約時点で事前入力しておける想定。
訪問直後に入力するのは B〜E のみ。

### 観察候補の選択順

段階ごとに、定番チェックと追加候補を同じ選択順で扱う。新しく選んだ語は末尾へ追加する。解除した語を並びから外し、残った語の相対的な順番は維持する。選び直した語は末尾へ入る。別の段階で同じ語を選んでも、選択と順番は独立している。

候補ボタンの配置は固定し、各段階に選択順を番号付きで表示する。保存には既存の `flow.<段階>.checks` 配列を使い、保存形式や保存キーは変更していない。保存後の再読み込み、再編集と無操作の再保存、JSONの入出力、バックアップ復元、記事素材への出力でも並びを保持する。入力途中のタブ切替も同様。

旧記録は保存された配列の並びを保持する。未知の観察語や空の保存値も、本人が解除するまで残す。旧記録の押下順を復元したり、新旧の並びの由来を識別したりする情報は持たない。旧記録へ語を追加しても、配列全体の押下順が確認できたとは扱わない。

画面には選択順（旧記録は保存された並び）と表示する。選んだ順は、施術の実際の順序や時刻を示すものではない。記事生成にも、並びから未記録の時刻や時間差、経過、出来事を補わないよう指示する。

この順序保持の対象はDの6段階の観察候補に限る。Bの評価理由、Dのハイライトメモと残念ポイントへ文章を追記する操作、Cの属性チップ、Eの再訪意向には適用しない。再訪を含む新規入力へ、前回の観察候補や順番を事前入力しない。操作時刻や全操作ログ、同じ語の複数回記録、手動での並べ替えは扱わない。
