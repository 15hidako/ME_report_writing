# 記事ボードとローカル起動

更新日：2026-11-13

入力画面、記事ボード、週次の在籍・出勤確認について、どこで開き、何をどこに保存するかをまとめる。全体の流れは概念図 [system-overview.drawio](diagrams/system-overview.drawio) にもある。draw.io デスクトップか、エディタの draw.io 拡張で開く。

実データ、実際のフォルダの場所、店やセラピストのURLはこの文書と図に書かない。

## 画面の役割

| 画面 | 開く端末 | 使う場面 |
|---|---|---|
| 入力画面の「入力」 | スマホとPC | 訪問の記録を入れて保存する。「保存して共有」でSlackへ渡す |
| 入力画面の「履歴」 | スマホとPC | 記事プロンプトのコピー、投稿URLの登録、まとめ記事のプロンプト、データの保存と読込 |
| 入力画面の「サムネ」 | スマホとPC | 回答を選んでサムネを作る。ボードの販売型に合うレイアウトが初めから選ばれる |
| 記事ボード | PCだけ | 記事の段階の管理、原稿のコピー、まとめ記事のカード、週次確認の同期 |

ボードへの入口は、画面の幅が1024px以上でマウスを使うときだけ、入力画面の上部と履歴カードに出る。スマホでは出ない。

## 1本の記事ができるまで

1. 入力画面で訪問を記録し、「保存」か「保存して共有」を押す。
2. 履歴カードの「プロンプト」か「名前公開版」を押し、出勤確認日を入れてコピーする。ボードのカードは「回答済み」から「プロンプト出力」へ進む。
3. Claude にプロンプトを貼り、原稿を書いてもらう。PCで保存先を設定してある場合は、Claude Code が原稿フォルダへ4つのファイルを書き出す。
4. ボードで原稿を読み込むと、カードが「推敲中」へ進み、タイトル、タグ、無料部分、有料部分をそれぞれコピーできる。
5. 本人が wakust の投稿画面へ手で貼って投稿する。投稿と販売設定は自動にしない。
6. 投稿URLを入力画面の履歴かボードで登録する。カードは「投稿済み」へ移る。
7. 週に1回、ボードの「同期」と週次確認のスクリプトで、投稿済みのセラピストの在籍と出勤を確かめる。

まとめ記事は、ボードの「+ 記事」でカードを作り、カードの「プロンプト」でコピーする。テーマはカードのタイトルを使う。対象に選べるのは投稿済みの回答だけで、別々のセラピストの投稿済み単体記事が6人分そろうまでは作れない。入力画面の「まとめ記事」からも同じプロンプトを作れる。

## 起動経路と保存領域

ブラウザの保存領域はURLごとに分かれる。同じPCでも、ポート番号やURLが違えば、回答もボードの状態も見えない。

| 起動経路 | URL | 使い道 |
|---|---|---|
| `start.bat` | `http://localhost:5173/` | 本人がPCで作業するときの正式な場所 |
| `.claude/launch.json` の `me-report-writer` | `http://localhost:5183/` | Claude が実画面を確かめる場所。確認用のデータを入れてよい |
| GitHub Pages | 公開URL | スマホで入力する場所 |

経路をまたいで回答を移すときは、移す元で「保存して共有」を使い、移す先の履歴で「回答を追加読込」を使う。「読込(JSON)」は全件を置き換えるので、1件ずつ足したいときには使わない。

## このPCだけの設定

リポジトリ直下の `.env.local` に、原稿フォルダと回答データフォルダを絶対パスで1行ずつ書く。`.env.local` は git の管理外にある。

```
VITE_ARTICLE_DIR=<原稿フォルダの絶対パス>
ME_ANSWER_DIR=<回答データフォルダの絶対パス>
```

設定したあとは `start.bat` を起動し直す。`VITE_ARTICLE_DIR` を設定したときだけ、次の2点が変わる。

- 記事プロンプトの末尾に、原稿4ファイルの保存先の指示が付く。
- プロンプトをコピーしたあと、Claude デスクトップアプリを開く(`claude://`)。

GitHub Pages の公開版にはこの値が入らないので、スマホではコピーだけになる。絶対パスでない値を書くと、入力画面を開いたときに理由を知らせ、設定がない場合と同じ動きにする。

`ME_ANSWER_DIR` は `start.bat` だけが使う。名前に `VITE_` を付けていないので、画面側には渡らない。

## 3つのフォルダ

どれもリポジトリの外に置く。原稿、確認結果、回答をリポジトリに入れないためである。

**原稿フォルダ**は、Claude Code が原稿を書き出す場所である。ボードの「原稿」では、`VITE_ARTICLE_DIR` と同じフォルダを選ぶ。中は `<通し番号4桁>-<回答ID>/standard` と `.../names` に分かれ、それぞれに `title.txt`、`tags.txt`、`free-part.html`、`paid-part.html` が入る。`standard` は通常版、`names` は名前公開版の原稿である。ボードは選んだフォルダの絶対パスを知ることができないので、`VITE_ARTICLE_DIR` と末尾のフォルダ名が違うときだけ知らせる。同じ名前の別フォルダは見分けられない。

**受け渡しフォルダ**は、ボードと週次確認のスクリプトがファイルをやり取りする場所で、ボードで最初に「同期」を押したときに選ぶ。中身は次の3つである。

| ファイル | 書く側 | 中身 |
|---|---|---|
| `targets.json` | ボード | 確認するセラピストのプロフィールURLと出勤表URL |
| `checks.json` | スクリプト | 在籍と出勤の確認結果 |
| `board-backup.json` | ボード | ボードの状態の控え |

ボードで選んだ2つのフォルダはブラウザが覚えている。変えるときは、ボードのツールバーの「⋯」から「原稿フォルダを変更」か「受け渡しフォルダを変更」を選ぶ。フォルダの読み書きは Chrome と Edge でできる。それ以外のブラウザでは「確認対象を書き出す」と「確認結果を読み込む」でファイルを手で受け渡す。

**回答データフォルダ**には、Slack で受け取った回答のJSONを置いておく。PCでダウンロードすると、ファイルは `me-report-<通し番号>.json` という名前でダウンロードフォルダに入る。`start.bat` は起動するたびに次のコマンドを実行し、そのファイルを `ME_ANSWER_DIR` のフォルダへ移す。手で実行してもよい。

```
node scripts/file-answers.mjs
```

移すのは名前が `me-report-` で始まる訪問記録のJSONだけで、ボードの控えのような訪問記録以外のファイルはそのまま残る。同じ中身のファイルがすでにあれば、ダウンロードフォルダ側を消す。同じ名前で中身が違うとき(直した回答を送り直したときなど)は、名前の末尾に中身から作った8文字を足して両方残す。移したファイルを画面に取り込むのは別の操作で、履歴の「回答を追加読込」を使う。

`ME_ANSWER_DIR` を書いていなければ、`start.bat` はこの整理をしない。移せなかったときは理由を表示していったん止まり、キーを押すとそのままアプリを起動する。

## 週次確認の手順

1. ボードで「同期」を押す。受け渡しフォルダに `targets.json` が書かれる。前回の `checks.json` があれば、その結果も読み込まれる。
2. リポジトリのフォルダで次を実行する。スクリプトは対象ごとに2秒ずつ間を空けてページを取りに行くので、件数が多いと時間がかかる。

   ```
   node scripts/weekly-check.mjs <受け渡しフォルダ>
   ```

3. もう一度ボードで「同期」を押す。今回の `checks.json` が読み込まれ、在籍なしや出勤なしのカードがボード上部の「要確認」に出る。

スクリプトは Node.js 24 で動作を確かめた。`.ts` のファイルを直接読むため、型の取り除きに対応していない古い Node.js では動かない。

## 新しい版への切り替え

入力画面とボードは、公開版が新しくなったことに気づくと読み込み直す。ただし、入力や共有の途中と、ボードでダイアログを開いている途中は勝手に読み込み直さず、画面上部に「新しい版に更新」のボタンを出す。開発サーバー(5173番、5183番)ではこの確認をしない。
