# 記事ボードとローカル起動

更新日：2026-11-13

入力画面、記事ボード、週次の在籍・出勤確認について、どこで開き、何をどこに保存するかをまとめる。PCでの作業は記事ボードから始め、ボードとClaude/Codexの操作だけで終わるようにしている([U-22](15-requirements-history.md))。全体の流れは概念図 [system-overview.drawio](diagrams/system-overview.drawio) にもある。draw.io デスクトップか、エディタの draw.io 拡張で開く。

実データ、実際のフォルダの場所、店やセラピストのURLはこの文書と図に書かない。

## 画面の役割

| 画面 | 開く端末 | 使う場面 |
|---|---|---|
| 入力画面の「入力」 | スマホとPC | 訪問の記録を入れて保存する。「保存して共有」でSlackへ渡す |
| 入力画面の「履歴」 | スマホとPC | 記事プロンプトのコピー、投稿URLの登録、まとめ記事のプロンプト、データの保存と読込 |
| 入力画面の「サムネ」 | スマホとPC | 回答を選んでサムネを作る。ボードの販売型に合うレイアウトが初めから選ばれる |
| 記事ボード | PCだけ | 回答の取り込み、記事プロンプトのコピー、記事の段階の管理、原稿のコピー、まとめ記事のカード、週次確認 |

ボードへの入口は、画面の幅が1024px以上でマウスを使うときだけ、入力画面の上部と履歴カードに出る。スマホでは出ない。

## 1本の記事ができるまで

1. スマホの入力画面で訪問を記録し、「保存して共有」で Slack へ送る。
2. Claude か Codex に、Slack の `me-report-inbox` の回答を `data/answers` へ保存するよう頼む。
3. `start.bat` でボードを開く(開いていれば、ボードの画面に戻る)。上部に「新しい回答」が出るので「取り込む」を押す。既存の回答の更新は、差分を見て確かめる。通し番号が重なったときは、ボード側の次の番号で取り込む。
4. カードの「プロンプト」か「名前公開版」を押し、出勤確認日を入れてコピーする。カードは「プロンプト出力」へ進み、Claude デスクトップアプリが開く。
5. Claude にプロンプトを貼る。Claude Code が原稿4ファイルを `data/articles` へ書き出す。
6. ボードへ戻ると原稿が読み込まれ、カードが「推敲中」へ進む。タイトル、タグ、無料部分、有料部分をそれぞれコピーできる。
7. 本人が wakust の投稿画面へ手で貼って投稿する。投稿と販売設定は自動にしない。
8. カードを「投稿済み」へ動かし、投稿URLを登録する。
9. 週に1回、ボードの「週次確認」を押す。投稿済みのセラピストの在籍と出勤を確かめ、結果をカードと上部の「要確認」に出す。

まとめ記事は、ボードの「+ 記事」でカードを作り、カードの「プロンプト」でコピーする。テーマはカードのタイトルを使う。対象に選べるのは投稿済みの回答だけで、別々のセラピストの投稿済み単体記事が6人分そろうまでは作れない。入力画面の「まとめ記事」からも同じプロンプトを作れる。

## 起動経路と保存領域

ブラウザの保存領域はURLごとに分かれる。同じPCでも、ポート番号やURLが違えば、回答もボードの状態も見えない。

| 起動経路 | URL | 使い道 |
|---|---|---|
| `start.bat` | `http://localhost:5173/` | 本人がPCで作業するときの正式な場所 |
| `.claude/launch.json` の `me-report-writer` | `http://localhost:5183/` | Claude が実画面を確かめる場所。確認用のデータを入れてよい |
| GitHub Pages | 公開URL | スマホで入力する場所 |

経路をまたいで回答を移すときは、移す元で「保存して共有」を使い、移す先の履歴で「回答を追加読込」を使う。「読込(JSON)」は全件を置き換えるので、1件ずつ足したいときには使わない。

## データの置き場所

回答、原稿、週次確認のファイルは、すべてPJフォルダ内の `data/` に置く。`data/` は git の管理外で、リポジトリには入らない。ボードは開発サーバー(`start.bat`)を通して `data/` を読み書きするので、フォルダを選ぶ操作や `.env.local` のパス設定はいらない。

| フォルダ | 書く側 | 中身 |
|---|---|---|
| `data/answers` | Claude/Codex(Slack から)、`start.bat` | 回答のJSON。ボードが新しいものを見つけて「新しい回答」に出す |
| `data/articles` | Claude Code | `<通し番号4桁>-<回答ID>/standard` と `.../names` に、`title.txt`、`tags.txt`、`free-part.html`、`paid-part.html`。`standard` は通常版、`names` は名前公開版 |
| `data/checks` | ボードと週次確認 | `targets.json`(確認するプロフィールURLと出勤表URL)、`checks.json`(確認結果)、`board-backup.json`(ボードの状態の控え) |

原稿のフォルダは回答IDで回答と結び付ける。先頭の通し番号は照合に使わない。

記事プロンプトの末尾には、`data/articles` の絶対パスを使った保存先の指示が付く。GitHub Pages の公開版では付かないので、スマホではコピーだけになる。

スマホから Slack へ送った回答をPCでダウンロードした場合も、`start.bat` が起動のたびにダウンロードフォルダの `me-report-*.json` を `data/answers` へ移す。同じ中身のファイルがすでにあればダウンロード側を消し、同じ名前で中身が違えば、中身から作った8文字を名前に足して両方残す。

ボードを `start.bat` 以外(GitHub Pages など)で開くと `data/` に届かないので、上部にその旨を出す。

## 週次確認

ボードの「週次確認」を押すと、次の順で進む。対象ごとに2秒ずつ間を空けてページを取りに行くので、件数が多いと数分かかる。その間、ボタンは「確認中…」になる。

1. 確認対象を `data/checks/targets.json` に書く。
2. 開発サーバーが `scripts/weekly-check.mjs` を実行し、結果を `checks.json` に書く。
3. 結果をボードに読み込み、在籍なしや出勤なしのカードを上部の「要確認」に出す。
4. ボードの状態の控えを `board-backup.json` に書く。

スクリプトは Node.js 24 で動作を確かめた。`.ts` のファイルを直接読むため、型の取り除きに対応していない古い Node.js では動かない。

## 新しい版への切り替え

入力画面とボードは、公開版が新しくなったことに気づくと読み込み直す。ただし、入力や共有の途中と、ボードでダイアログを開いている途中は勝手に読み込み直さず、画面上部に「新しい版に更新」のボタンを出す。開発サーバー(5173番、5183番)ではこの確認をしない。
