# ME Report Writer — プロジェクト計画(確定版)

2026-11-06追記：Claude Codeの元の案・合意を原則として引き継ぐ。[原要件の移植先](14-claude-requirements.md)と[出典・後の資料との差異](15-requirements-history.md)を参照する。この計画の原文は保持し、後半の作業記録を根拠に原案を縮小しない。

個人利用。メンズエステ訪問後、モバイルで簡易質問票に入力し、
wakust へ投稿できる形(HTML本文・タイトル・タグ・サムネイル)まで成型するツール。

## 全体フロー

```
訪問直後(iPhone)
  → PWA質問票に入力(5分以内、選択式中心) → localStorage に訪問レコード保存
  → 「生成プロンプトをコピー」 → Claude(アプリ/Web)に手貼り
  → 記事ドラフト(無料部HTML + 有料部HTML + タイトル + タグ + ポイント案)
  → Laptop/iPad で推敲
  → PWAのサムネイルジェネレーターで PNG 生成
  → wakust 投稿フォームへコピペ + 画像アップロード(手動)
```

- 生成エンジン: Claude 手貼り(API不使用・ゼロコスト)
- データ: 端末 localStorage のみ。外部送信は自分が Claude に貼る瞬間だけ
- 投稿の自動化はしない(規約・bot検知リスク回避)

## 販売戦略: 1アカウント2レイヤー + 派生生産モデル

複数アカウントでの同一ネタ出し分けは wakust 規約 3-3/3-4 で禁止のため不採用。
代わりに 1 アカウント内で以下を運用する。

### レイヤー構成
| レイヤー | 形式 | 役割 |
|---|---|---|
| カタログ面 | 宣伝用**無料**記事(1日1カテゴリー1記事まで) | エリア別の自分の体験談インデックス。スペック・評価の一部を見せて有料記事へ誘導(同カテゴリー内リンクOK) |
| フック面 | 有料体験談(シリーズ名+通し番号) | 店名・源氏名は有料側で開示。無料部分は序盤ストーリー+クリフハンガー |

### 1訪問 → 複数コンテンツ(規約準拠の派生4種)
1. **単体体験談** — 訪問直後に投稿する本体
2. **まとめ記事** — 個別体験談6本到達後に解禁(規約1-7)。「自分の体験からエリア別おすすめN選」。過去販売内容を含む旨を明記
3. **再訪記事** — 初回記事へのリンクを本文上部に明記(規約1-1)。差分中心で低コスト
4. **ノウハウ記事** — 訪問不要。初心者ガイド・用語解説・店選び術など。投稿頻度の維持に使う

+ セット販売・定期購読(プラットフォーム公式機能)を成熟後に重ねる。

### 価格戦略
- 立ち上げ期: 100〜300pt で部数と★レビューを蓄積
- 実績が付いたら「○部突破」をタイトルに追記、シリーズ後半で 1,000pt 超へ
- まとめ記事・セットは中〜高単価

## wakust 規約の遵守ポイント(要点メモ)

出典: https://wakust.com/rule/ (2026-07 時点)

- 1-1: 同一内容の複数投稿禁止。再販は「[再販]」明記。ME等へ**別名義**で投稿した同一内容の掲載禁止
- 1-5: 有料記事は伏せ字・イニシャルで詳細不明はNG。ワクスト内で完結させる
- 1-6: リンクだけの有料記事NG。テキストで内容を併記
- 1-7: まとめ記事は個別体験談6本後に解禁
- 1-9: 1カテゴリー1日4記事まで。宣伝用無料記事は1日1カテゴリー1記事
- 2-1: 体験の実在性について運営から予約スクショ等の提出を求められることがある → **証跡を残す**
- 2-6: マンション名・階数・部屋番号は無料/有料問わず記載禁止
- 3-x: 複数アカウントは事前相談必須。同ジャンル・同地域・同ネタは不可 → 不採用の根拠
- ME への同時投稿はしない(別名義同一内容の禁止 + ME 側の AI 投稿ペナルティ)

## 現在の作業状況（2026-11-03）

初期実装と初回の実運用検証は完了した。Phase 4の改善はコミット`3a4f2e0`、運用再開時の改修は[再開計画](04-restart-plan.md)、端末間の共有は[Slack引き継ぎ計画](10-slack-handoff-plan.md)に記録している。

| 対象 | 状態 | 完了条件 |
|---|---|---|
| 料金の記事素材への出力 | 修正・検証済み | コース代、指名料、オプション代を、未確認と0円を区別して渡す。総支払額や割引額を推測しない |
| 再訪記録の参照保護 | 修正・検証済み | 他の再訪記録が参照する記録を削除できず、保存内容とバックアップを保つ |
| 古い編集画面からの上書き保護 | 修正・検証済み | 他の画面の変更を検出して上書きを止め、手元の入力を残す。破棄確認後に最新内容を開き直せる |

| 改修後の実記事による通し確認 | 未実施 | 新しい共有経路で受け取った実際の回答から、記事作成、本人の推敲、手動投稿までを確認する。テスト回答を実体験として投稿しない |
| 入力時間と素材の評価 | 未実施 | 実際の訪問メモで5分以内に入力できるか計測し、記事に必要な素材の不足と書き直しを記録する |
| 実機と読み上げの評価 | 未実施 | iPhoneで片手入力とエラー欄への移動を試し、スクリーンリーダーで必須項目と修正先を確認する |

デスクトップとスマートフォン幅の表示確認は、実機での片手操作や読み上げの評価とは分けて扱う。下書き自動保存、オフライン起動、Slackの固定チャネルへの直接送信や自動受信は、現在の実装対象に含めない。

複数画面で同じ回答を編集している場合、保存前に編集開始時と最新の内容を照合する。別画面で内容が変更されていたら保存と共有を中止し、手元の入力を保持する。入力内容を控えたうえで履歴から同じ回答の編集画面を開き直し、未保存入力の破棄を確認してから最新内容を表示する。投稿URLのみの変更であれば最新値を引き継ぐ。未編集の回答を再共有する場合は最新の保存内容を渡し、古いフォームからの後続の上書きは許可しない。

PCでは[start.bat](../start.bat)からローカル版を起動できる。ローカル版とGitHub Pages版では保存領域が異なり、ブラウザを変えた場合も既存データは自動移行されない。移行にはJSONの保存と追加読込を使う。

### 今回の確認結果

料金、削除保護、古い編集画面からの上書き保護を対象とする回帰テストを26件追加し、全288テスト、型チェックとビルド、差分検査が成功した。TypeScriptレビューで見つかった競合後の開き直し処理も修正し、最終のコードレビューとTypeScriptレビューで追加指摘はなかった。検証完了後、2026-11-03に利用者からコミット・push・公開の明示許可を得た。`docs/10-slack-handoff-plan.md`、新しい料金テスト、`start.bat`を含む12ファイルを対象とし、実回答JSONは含めない。公開処理の結果はGitHub Actionsで確認する。

通常のChromeでローカル版の履歴画面を開けたが、拡張機能のファイルアクセス許可がなく追加読込を完了できなかった。通常のファイル選択への切替も、操作基盤がブラウザURLを確認できず停止したため未実施。権限設定は変更しておらず、通常ブラウザの保存データも変更していない。

過去にiPhoneから復旧した4件入りのJSONと作業用コピーは、リポジトリ外に残っていた。現行スキーマでの読み込み、メモリ上での保存と再読込、料金の記事素材への出力を4件とも確認した。1件ずつの追加読込と再取り込みも確認し、重複は生じなかった。原本は変更せず、実回答や検証用コピーはリポジトリに入れていない。通常のPCブラウザへの取り込みと実記事の確認は引き続き未完了である。

文書の変更段落は`stop-ai-slop-jp`を適用し、Orcaが停止していたためAntigravity CLIを直接実行してGemini 3.8 Flash Highで整え、原文と照合した。実回答や実機証跡、設定本文、認証情報はリライトに渡していない。上記の実行結果は親が追記した。
